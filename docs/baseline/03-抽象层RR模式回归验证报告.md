# Lab3 调度抽象层 RR 模式回归验证报告

## 1. 验证目的

确认在引入调度器抽象层、支持 RR/MFQ 双模式切换后，原生 RR 调度的运行行为与 `main-baseline` 基线版本完全一致；验证抽象层封装未破坏内核机制层逻辑，系统稳定性、调度表现符合预期，作为后续 MFQ 开发的可信底座。

## 2. 验证环境

- 运行平台：希冀平台 Web 虚拟机（Ubuntu 24.04）
- 硬件平台：QEMU 仿真 riscv-virtio 平台，双核
- 交叉工具链：riscv64-unknown-elf-gcc
- 验证分支：`dev-mfq-scheduler`
- 调度模式：`DEFAULT_SCHED_MODE = SCHED_MODE_RR`
- 固件：OpenSBI v1.3

## 3. 验证步骤

1. 进入项目目录，执行 `make clean` 清理所有历史编译产物
2. 执行 `make build` 完整编译内核
3. 执行 `make fs` 生成 FAT32 文件系统镜像
4. 执行 `make run` 启动 QEMU 加载内核
5. 进入 xv6 shell 后，执行 `ls`、`echo` 等基础命令验证系统交互
6. 执行 `schedtest` 验证调度程序运行表现
7. 正常退出 QEMU，确认全程无 panic、无死锁

## 4. 验证结果

### 4.1 启动模式标识正常

内核启动早期成功打印调度器模式标识：

```
[sched] Using scheduler: Round-Robin (RR)
```

说明调度器初始化、编译期模式选择、启动打印链路全部正常工作。

### 4.2 内核启动正常

- OpenSBI 引导正常，双核 hart 初始化完成
- 内核无 panic、无异常报错，成功进入 `-> / $` shell 提示符
- 系统初始化流程完整，`init` 进程与 `sh` 进程正常启动

### 4.3 基础命令交互正常

- `ls` 可正常列出文件系统目录，所有用户态程序完整可见
- `echo` 等基础命令执行正常，无异常崩溃
- 说明系统调用、文件系统、终端交互等基础功能完好，抽象层改动未引入副作用。

### 4.4 调度行为与基线一致

执行 `schedtest` 输出：

```
set_timeslice FAILED (CP① not done?)
```

该现象与 `main-baseline` 原生基线完全一致：

- `set_timeslice` 对应实验指导书 CP① 优先级调度系统调用，原生 RR 版本本就未实现该接口
- 报错属于预期内的功能未实现，并非调度抽象层引入的错误
- 程序可正常执行、正常返回 shell，说明 RR 调度主逻辑运行正常，进程创建、切换、退出链路完好。

### 4.5 系统稳定性

- 内核运行全程无死锁、无随机崩溃
- 多次执行命令、重复运行测试程序，表现稳定
- 退出 QEMU 正常，无异常卡住

## 5. 验证结论

✅ **RR 模式回归验证通过**。
调度器抽象层的引入严格遵循「机制与策略分离」原则，仅替换了策略层入口，未改动 `scheduler` 主循环、锁、re-check、上下文切换、页表切换等任何机制层代码。RR 模式下系统启动、运行、调度行为与原生基线 100% 一致，抽象层架构无侵入性破坏，可作为后续 MFQ 算法开发的稳定底座。
